# 部署到服务器（自建主机方案）

> 云端托管方案（Vercel + Render + Render PostgreSQL）请看根目录 [`Deploy_Guide.md`](../Deploy_Guide.md)。
> 本文件是「自己有一台服务器」时的备选方案。

前端：React + Vite，构建产物 `dist/`。
后端：Spring Boot 3（jar），监听 8080。
数据库：**PostgreSQL 15**（JSONB 字段依赖 PG，不能用 MySQL）。
入口：Nginx 同时托管静态资源和反代 `/api`。

## 方案 A：Docker Compose（推荐）

服务器上只需装好 Docker 和 docker-compose 插件。

```bash
# 1. 前端构建参数已在 .env.production 里，接口走相对路径 /api，由 Nginx 转发
# 2. 后端先在本机打包
cd backend && mvn clean package -DskipTests     # 得到 target/*.jar
#    把 jar 名改成 smart-materials-server.jar（或改 compose 里的 command）

# 3. 启动整套
cd deploy
docker compose up -d --build

# 4. 看日志 / 停止
docker compose logs -f backend
docker compose down
```

访问 `http://服务器IP` 即可。

## 方案 B：不用 Docker

```bash
# 前端
npm ci
npm run build                                   # 产出 dist/
sudo mkdir -p /var/www/smart-materials
sudo cp -r dist/* /var/www/smart-materials/

# 后端（用 systemd 守护）
sudo tee /etc/systemd/system/sm-backend.service > /dev/null <<'EOF'
[Unit]
Description=Smart Materials Backend
After=network.target

[Service]
ExecStart=/usr/bin/java -jar /opt/smart-materials/backend.jar
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now sm-backend
```

Nginx 站点配置用 `deploy/nginx.conf`，**把 `proxy_pass` 改成 `http://127.0.0.1:8080`**（宿主机部署没有 `backend` 这个服务名），监听 80，root 指向 `/var/www/smart-materials`。

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 上 HTTPS

```bash
sudo certbot --nginx -d 你的域名
```

## 必须注意的坑

1. **Vite 环境变量是构建时注入的**，不是运行时。改了接口地址或 Mock 开关，必须重新 `npm run build`。
2. **SPA 刷新 404**：`try_files $uri $uri/ /index.html;` 不能少，否则 `/materials` 这类子路径刷新会 404。
3. **后端端口别暴露到公网**：只让 Nginx 转发，服务器安全组不要放通 8080 和 5432。
4. **改掉默认密码**：`docker-compose.yml` 里的 `change_me_please` 必须替换。
5. **同源部署不需要 CORS**：前端和 API 同域名，浏览器不会跨域；若前后端分在不同域名，后端要开 CORS。
6. **关闭 Mock**：生产构建用 `VITE_USE_MOCK=false`，否则请求仍走 `src/mock/api.ts` 打不到真接口。
